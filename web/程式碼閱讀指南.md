# 從這裡開始讀程式碼

這個專案使用 TypeScript、React 和 Next.js。整理的原則是讓步驟更容易看懂，同時保留原本的功能、判斷順序、回傳值及提示文字。

## 資料夾怎麼分工

| 位置 | 可以把它想成 | 內容 |
| --- | --- | --- |
| `src/app` | 網站的入口 | 網頁、網址對應的頁面，以及 API 入口 |
| `src/components` | 畫面上的零件 | 表單、按鈕、課表、對話框等 React 元件 |
| `src/services` | 處理工作的地方 | 查詢資料、儲存課表與其他業務流程 |
| `src/lib` | 共用工具箱 | 網址整理、登入檢查、型別與共用設定 |
| `supabase/migrations` | 資料庫變更紀錄 | 建立或修改資料表及權限的 SQL |

例如想找某個教練頁面：先在 `src/app` 找到該頁的 `page.tsx`，再看它 import 了哪些元件；元件需要儲存資料時，接著追蹤對應的 API 與 service。不是每個頁面都會經過完全相同的流程。

## 建議先讀的小檔案

1. `src/lib/external-url.ts`：整理網址。練習看輸入、變數、`if / else if`、回傳值與 `try / catch`。
2. `src/lib/auth/callback-redirect.ts`：檢查登入後要去的路徑。練習看允許清單與預設結果。
3. `src/lib/auth/password-rules.ts`：逐步檢查密碼，將錯誤轉成使用者看得懂的訊息。
4. `src/lib/auth/identity-binding.ts`：用登入者 ID 找到個人資料，理解零筆、一筆、多筆三種結果。

## 常見語法的小字典

| 語法 | 意思 |
| --- | --- |
| `const name = value` | 給一個值取名字；這個變數不能再指向別的值 |
| `let name = value` | 這個變數之後還會被重新指定 |
| `return value` | 結束目前函式，把結果交還給呼叫者 |
| `if (...) { ... }` | 條件成立才執行括號裡的內容 |
| `===` | 比較兩邊的值與型別是否相同 |
| `&&` | 左邊成立才繼續判斷右邊；它不一定回傳布林值 |
| `||` | 左邊是假值才取右邊；它也不一定回傳布林值 |
| `value ?? fallback` | 只有 value 是 null 或 undefined 時，才改用 fallback |
| `value?.name` | value 是 null 或 undefined 時，回傳 undefined，不繼續讀 name |
| `list.filter(...)` | 建立只包含符合條件項目的新陣列 |
| `list.map(...)` | 將每個項目轉換後，組成新陣列 |
| `async / await` | 等待非同步工作完成；先檢查失敗時如何處理 |
| `type`、`interface` | 描述資料預期長什麼樣子，本身不會檢查執行時的資料 |
| `import type` | 只匯入型別，不會產生實際執行的功能 |

## 為什麼不能把所有語法都直接換掉

改寫時需要維持原本的順序。例如密碼同時太短又不一致，程式原本先回報「太短」，整理後也必須一樣。空字串、null、undefined 也不能隨意當成相同的東西。

React 的 Hook 依賴、資料庫查詢順序及登入權限可能直接影響功能。即使另一種寫法看起來更簡單，也不能為了可讀性順手改變它們。

第一批整理集中在上述四個工具檔。大型課表、團隊管理、API 與資料庫流程仍保留原寫法，並非整份專案已改寫完成。
